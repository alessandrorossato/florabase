## Change

- `scripts/feature_batch.py`:
  - A batch request carries a reviewed `summary` (`batch_summary`). It is one plain line of
    10 to 72 characters, with no surrounding spaces, control characters, backticks,
    hexadecimal tokens of 7 or more characters, or Conventional Commit type prefix.
  - `prepare` refuses a plan without a valid summary before it merges anything, and writes the
    summary into the manifest.
  - `load_manifest` rejects an invalid summary. A correction already must equal its original
    manifest apart from `correction`, so the summary cannot change after delivery starts.
  - `title_body` titles the PR `chore(release): <summary> (batch <id>)`, at most 100
    characters. The body starts with the summary and keeps the head, the pinned main, the
    manifest path, the migration flag and every source ID, branch and full commit.
  - A manifest without `summary` keeps the original title and body byte for byte. The
    manifest version is unchanged.
- `docs/development-workflow.md`: the request and title rules.

Delivery, branch protection, squash proof, exact-head PR matching and the correction workflow
are not changed.
