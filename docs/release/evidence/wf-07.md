## Change

- `scripts/feature_batch.py`:
  - A batch request carries a reviewed `summary` (`batch_summary`). It is one plain line of
    10 to 72 characters. It may not have surrounding spaces, control characters or backticks,
    a run of 7 or more hexadecimal characters that contains a digit (a commit-like reference),
    or a leading `word:` or `type(scope):` prefix in any case. Words made only of the letters
    a to f, such as "feedback" and "decaffeinated", are allowed.
  - One pure function, `summary_title`, builds and validates the whole title
    `chore(release): <summary> (batch <id>)`. It checks the summary and limits the complete
    title, including the prefix and batch id, to 100 characters. It never truncates.
  - `prepare` calls it before it merges anything or changes HEAD, and writes the summary into
    the manifest.
  - `load_manifest` calls it for any manifest with a summary, so an invalid final manifest
    fails on load instead of at delivery. A correction already must equal its original
    manifest apart from `correction`, so the summary cannot change after delivery starts.
  - `title_body` uses the same function for the title. The body starts with the summary and keeps the head, the pinned main, the
    manifest path, the migration flag and every source ID, branch and full commit.
  - A manifest without `summary` keeps the original title and body byte for byte. The
    manifest version is unchanged.
- `docs/development-workflow.md`: the request and title rules.

Delivery, branch protection, squash proof, exact-head PR matching and the correction workflow
are not changed.
